# Recorte fase 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build phase 1 of Recorte: WXT extension (capture + pre-save dialog + offline queue), Node/Hono server (accounts, items, light AI, Meilisearch hybrid search), React/HeroUI gallery, shipped as `docker compose` with 2 services.

**Architecture:** pnpm monorepo. `packages/shared` holds the Zod contract used by all apps. The server stores each item as files + `meta.json` (source of truth), mirrors to SQLite (`node:sqlite`) for listing, and indexes into Meilisearch for ⌘K search. A single in-process worker runs the AI pipeline (sharp + SigLIP2 int8 via transformers.js + deterministic keywords).

**Tech Stack:** Node 24, TypeScript, pnpm workspaces, Hono, `node:sqlite`, `@node-rs/argon2`, sharp, `@huggingface/transformers` 4.3.2, Meilisearch v1.56.1 + `meilisearch` JS client, Vite 8 + React 19 + HeroUI v3 + Tailwind 4, WXT, Zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-recorte-design.md` (read it; this plan argues from it).

## Global Constraints

- UI copy pt-PT; identifiers in English.
- Gallery look = `prototype/gallery` (black `#000`, Albert Sans 200–500, fades/glows, marquee, masonry, ⌘K/Ctrl+K and `/`).
- One owner account (§16). Every query and every Meilisearch search filtered by `userId` server-side.
- Images only via `GET /api/items/:id/files/:name` with auth. No public static image folder.
- `PATCH` touches only the `user` block. AI never writes `user`; reprocess never touches `user`.
- AI tags only from the closed vocabulary; visual group emits only `modo escuro`, `gradiente`, `imagens`.
- SigLIP2 `onnx-community/siglip2-base-patch16-224-ONNX`, vision `int8`; labels from committed `packages/ai/labels.siglip2.json` (fp32 text encoder, generated by script).
- Meilisearch `getmeili/meilisearch:v1.56.1`, internal network only; embedder `ml` = huggingFace `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; `semanticRatio` 0.6.
- Listing via SQLite keyset `createdAt DESC, id DESC`; never via Meilisearch.
- Full page max 12 000 CSS px; area selection limited to the viewport; client encodes WebP q≈0.9; server `original.webp` max width 3200, `thumb.webp` width 640.
- Versions: app = `MAJOR.MINOR.<commits since tag>`, extension = `MAJOR.MINOR.<commits touching apps/extension|packages/shared since tag>`; no tag → `0.0.<n>`; only integers.
- Trash: soft delete, purge after 30 days.
- Password reset: `recorte reset-password <email>` CLI inside container.

## Review Focus

1. Upload while server/Meilisearch is down → item still saved to disk + SQLite; search indexing retried by the job (server test `uploads succeed when search is unavailable`).
2. Very tall full-page capture (> 12 000 px) → truncated, `meta.truncated = true`, no crash (extension unit test of `planFullPageStrips`).
3. Session expired / device token revoked → gallery redirects to `/login`; extension shows "Volta a ligar a extensão" and keeps queue (server test `revoked device gets 401`; extension queue test keeps item on 401).
4. Tag with accents/uppercase/duplicates in the dialog (`"Lisboa ", "lisboa"`) → normalized once (`normalizeTag` test in shared).
5. Deleting an item hides it from listing, tag counts and search immediately; restore brings it back (server test `delete then restore`).

### Task 2: packages/ai — classifier, colors, keywords

**Files:** `packages/ai/src/{vocab,classify,colors,keywords,index}.ts`, `packages/ai/scripts/build-labels.mjs`, `packages/ai/labels.siglip2.json` (generated, committed), tests.

**Produces:**
- `createClassifier({modelDir?: string, threads?: number}): Promise<{classify(img: Buffer): Promise<{tipo: string[]; visual: string[]; scores: Record<string, number>}>}>` — letterbox (top region ratio ≤ 1.5, background = dominant color), group softmax ×100, `tipo` top-1 if p ≥ 0.30, visual each if group-prob ≥ 0.45 and label ∈ informative set.
- `extractColors(img: Buffer): Promise<{dominant: string; names: string[]}>` — 3-colour palette → names from 12-name table (preto, branco, cinzento, vermelho, laranja, amarelo, verde, azul, roxo, rosa, castanho, bege).
- `extractKeywords(input: {title?: string; text?: string; headings?: string[]; description?: string; site?: string}, max = 12): string[]` — pt+en stopwords, unigrams+bigrams, frequency × position weighting, title/heading boost.
- `VOCAB` (from `prototype/ai-bench/vocab.mjs`, `assunto` group dropped) and `labelSynonyms(tag): string[]` (pt name + English label words) for search indexing.

- [ ] Tests: `extractColors` on a solid `#1d4ed8` PNG → names contains `"azul"`; `extractKeywords({title:"Pastel de nata – Wikipedia", text:"pastel de nata is a Portuguese egg custard tart pastry"})` includes `"pastel de nata"` or `"pastel"` and excludes `"is"`; classifier test (skipped unless `RUN_MODEL_TESTS=1`) on `prototype/gallery/public/shots/osm-lisboa-1-t.webp` → `tipo` = `["mapa"]`.
